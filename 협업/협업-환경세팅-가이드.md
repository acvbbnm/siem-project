# 협업 환경 세팅 가이드 — 로컬 ESXi 랩을 둘이 함께 쓰기

> 이 랩은 **로컬 호스트의 ESXi 가상머신**으로 구성돼 있다(VyOS·pfSense·Bee-box·Splunk·mng/att-mint).
> 다른 사람과 협업하려면 "그 사람이 이 로컬 랩에 어떻게 닿게 할 것인가"를 정해야 한다.
> **협업이 확정되면** 아래 중 하나를 골라 세팅한다. (현재는 참고용, 미확정)
>
> ⚠️ 보안 원칙: **홈 공유기에 포트포워딩으로 랩을 인터넷에 직접 노출하지 않는다.**
> 반드시 VPN/오버레이 또는 원격제어 방식으로만 접근을 연다.

---

## 방식 비교

| 방식 | 실시간 동시작업 | 세팅 난이도 | 상대 PC 부담 | 추천 용도 |
|------|:---:|:---:|:---:|------|
| A. 원격 데스크톱 (mng-mint 공유) | △ (한 화면 공유) | ★☆☆ | 없음 | 같이 보며 학습/시연 |
| B. Tailscale 서브넷 라우팅 | ○ (각자 자기 PC) | ★★☆ | 없음(랩은 내 호스트) | **제대로 된 red/blue 협업** |
| C. OVA 내보내기 | ✕ (각자 별도 랩) | ★★☆ | 큼(6VM 구동) | 각자 병렬 연습 |

> **추천:** 가볍게 시작은 **A**, 실제로 같이 하려면 **B**. 아래는 방식별 상세 절차.

---

## 방식 A. 원격 데스크톱 — 가장 간단

`mng-mint`(10.0.50.100)는 이미 랩 안에 있어 Splunk·pfSense GUI에 바로 닿는다.
이 데스크톱 화면을 상대와 공유한다.

**절차**
1. mng-mint에 원격제어 도구 설치 — **AnyDesk** 또는 **RustDesk**(오픈소스) 권장, 또는 RDP/VNC.
   ```bash
   # 예: RustDesk (Linux Mint)
   # 공식 .deb 내려받아 설치 후 실행, 표시되는 ID/비밀번호를 상대에게 전달
   ```
2. 상대는 같은 도구를 깔고 **ID/1회용 비밀번호**로 mng-mint에 접속.
3. mng-mint 브라우저로 Splunk(`http://10.0.100.50:8000`)·pfSense GUI를 함께 사용.

**장점** 라우팅 설정 불필요, 오늘 바로 가능.
**한계** 한 화면을 같이 보는 방식이라 각자 다른 작업은 어렵다(시연·페어 학습용).

## 방식 B. Tailscale 서브넷 라우팅 — 각자 자기 PC로 동시 접속 (권장)

랩 안의 리눅스 VM 하나를 **"서브넷 라우터"** 로 만들어, 상대 노트북이 오버레이 VPN을 통해
랩 내부 IP(Splunk·pfSense 등)에 **직접** 닿게 한다. 홈망을 인터넷에 노출하지 않아 안전하다.

> 여기서는 관제(Blue) 접근을 위해 **mng-mint**를 서브넷 라우터로 쓴다(Splunk·pfSense가 목표).
> 상대가 공격(Red)까지 하려면 **att-mint**에도 Tailscale를 별도로 깔면 된다(아래 5번 참고).

### 1) 서브넷 라우터(mng-mint)에 Tailscale 설치
```bash
curl -fsSL https://tailscale.com/install.sh | sh
```

### 2) IP 포워딩 활성화 (라우터 역할 필수)
```bash
echo 'net.ipv4.ip_forward = 1'          | sudo tee -a /etc/sysctl.d/99-tailscale.conf
echo 'net.ipv6.conf.all.forwarding = 1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf
sudo sysctl -p /etc/sysctl.d/99-tailscale.conf
```

### 3) 랩 내부 대역을 광고하며 접속
```bash
# 관제에 필요한 대역: inner(Splunk), mng, dmz(Bee-box)
sudo tailscale up --advertise-routes=10.0.100.0/24,10.0.50.0/24,10.0.10.0/24
```
- 출력되는 인증 URL을 브라우저로 열어 **본인 Tailscale 계정으로 로그인**.
- 계정이 없으면 무료로 생성(개인용 무료 플랜으로 충분).

### 4) Tailscale 관리 콘솔에서 라우트 승인
- https://login.tailscale.com/admin/machines → mng-mint 항목의 **"Subnet routes"** 를
  **Edit route settings → 해당 라우트 체크 → Save**.
- (승인해야 광고한 대역이 실제로 라우팅된다.)

### 5) (선택) 공격용 att-mint도 참여시키기
상대가 att-mint에서 공격까지 하려면, att-mint에도 위 1)~3) 방식으로 Tailscale 설치.
- att-mint는 단순 접속 대상이면 라우트 광고 없이 `sudo tailscale up` 만 해도
  상대가 att-mint에 **직접(SSH/RDP)** 붙을 수 있다.

### 6) 상대(협업자) 측 설정
- 상대 PC(Windows/Mac/Linux)에 Tailscale 설치 → 로그인(당신이 초대하거나 같은 조직으로).
- **서브넷 라우트 수신 켜기**:
  - Windows/Mac: 트레이 아이콘 → **"Use Tailscale subnet routes"** 활성화.
  - Linux: `sudo tailscale up --accept-routes`

### 7) 접속 확인
상대 PC에서:
```bash
ping 10.0.100.50                 # Splunk 도달 확인
# 브라우저: http://10.0.100.50:8000  (Splunk)
#           https://10.0.50.1        (pfSense GUI, LAN)
```

### ⚠️ 방식 B 주의사항
- **IP 대역 충돌**: 상대 집 공유기가 `10.0.x.x`를 쓰면 충돌한다. 그럴 땐 상대 로컬망과 겹치지
  않게 하거나, 필요한 호스트만 라우팅한다.
- **경로 도달성**: mng-mint가 서브넷 라우터이므로, mng-mint에서 각 대역(10.0.100.x 등)이
  실제로 `ping` 되는지 먼저 확인. 안 되면 pfSense 규칙에서 mng→해당 대역 접근을 허용해야 한다.
- **ESXi 호스트가 켜져 있어야** 랩 전체가 살아 있다. 협업 시간대를 미리 맞춘다.

## 방식 C. OVA 내보내기 — 각자 자기 랩

각자 동일한 구성의 랩을 따로 돌리는 방식(실시간 협업은 아님).

**절차**
1. ESXi/vSphere에서 각 VM을 **OVF/OVA로 Export**.
2. 네트워크 구성(att/rf/dmz/inner/mng 가상 스위치)과 IP 설정 문서를 함께 전달.
3. 상대가 자기 ESXi/VMware Workstation에 Import 후 동일 네트워크 재구성.

**주의** 6개 VM 구동은 무겁다 — 상대 PC의 **RAM/CPU/디스크** 여유를 먼저 확인.

## 협업 시 공통 운영 규칙

- **계정 분리**: Splunk 사용자·pfSense 관리자 계정을 각자용으로 나눠, 작업 이력이 섞이지 않게 한다.
- **역할·시간 조율**: 누가 att-mint(공격)/누가 mng-mint(관제)를 언제 쓸지 미리 정한다
  (동시 red/blue 실습의 핵심).
- **변경 기록**: 방화벽 규칙·Snort 설정을 바꿀 땐 Phase 2의 "대응 규칙 on/off 순서표"를 함께 본다.
- **정리**: 한 사이클 후 Phase 1의 실습 정리(Cleanup)를 함께 수행한다.
- **보안**: 절대 포트포워딩으로 랩을 공개하지 않는다. VPN/오버레이/원격제어만 사용.
